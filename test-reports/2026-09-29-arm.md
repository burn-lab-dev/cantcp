# ARM smoke report — 2026-09-29

**English** | [Русский](2026-09-29-arm.ru.md)

Developed by **[BURN-LAB](https://burn-lab.ru)** — embedded software
development: Linux, drivers, CAN and industrial telemetry.

## Environment

- device: an `aarch64` single-board computer running Ubuntu 22.04 (jammy),
  accessed over ssh as root;
- package: `cantcpd 0.1.0` / `cantcp-cli 0.1.0`, **arm64**, installed from
  the project APT repository (`https://burn-lab-dev.github.io/cantcp`);
- bus: `vcan0`, MTU 72;
- client side: an amd64 workstation with the same APT binaries, plain and
  TLS 1.3 over the local network.

## Checks

| Check | Result |
|---|---|
| Install arm64 `.deb` from the APT repository | package installed, unit shipped with `AF_NETLINK` |
| Bring up `vcan0` (MTU 72) with the module | ok |
| Plain exchange, client (amd64) → daemon (arm64) → bus | 3/3 frames (classic 8 bytes, extended, 8-byte data), echoed to the client, seen by `candump` on the device |
| Statistics | `frames_read=3`, `frames_written=3`, no errors |
| Load over the network: 5000 frames, 200 µs interval | **5000/5000** seen by `candump`, `dropped=0` |
| Reverse direction: `cangen` on the device, 2000 frames | **2000/2000** at the client, data lengths 0..8 |
| TLS 1.3 with mutual TLS over the network | exchange delivered, `openssl s_client` reports `TLSv1.3` + `TLS_AES_128_GCM_SHA256` |
| mTLS without a client certificate | rejected by the server (`client didn't provide a certificate`) |
| Resources | plain daemon RSS **6.8 MB**, TLS daemon **7.8 MB**, 8 file descriptors |

## Notes

- The certificate pair generated for the test initially failed with
  `certificate has expired or is not yet valid`: `openssl x509 -req` sets
  `NotBefore` to the issuing machine's clock, and the device clock was a few
  seconds behind. The retry a few seconds later succeeded — a bench artefact,
  not a defect.
- After the tests the device was cleaned up completely: packages purged, the
  system user and group removed, configuration, certificates, logs and
  `vcan0` deleted; `dpkg -l`, `pgrep` and the filesystem show no leftovers.

## Verdict

The arm64 build installs from the project repository, starts, serves plain
and mutual-TLS traffic over the network and holds a full-rate load without
losses or leaks; the amd64 and arm64 binaries interoperate byte for byte.
