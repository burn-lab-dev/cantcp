# Участие в разработке

[English](CONTRIBUTING.md) | **Русский**

Разрабатывается **[BURN-LAB](https://burn-lab.ru)** — встраиваемый Linux:
драйверы, CAN и промышленная телеметрия.

Спасибо за время, уделённое проекту. Маленькие сфокусированные изменения
ревьюить проще всего; для большой фичи сначала откройте issue, чтобы
договориться о форме.

## Требования

- Go 1.24 или новее; CI дополнительно проверяет 1.26.
- `gofmt`, `go vet`, `go test -race` должны проходить.
- Только стандартная библиотека: сторонних зависимостей в проекте нет, и мы
  намерены так и оставить.
- Conventional Commits в сообщениях коммитов (`feat:`, `fix:`, `docs:`,
  `test:`, `chore:`, ...).

## Цикл разработки

```sh
make build     # bin/cantcpd, bin/cantcp-cli
make test      # go test -race ./...
make vet
make fmt       # проверка gofmt
make cross     # linux/amd64, linux/arm64, linux/armv7
make deb       # .deb-пакеты (нужен dpkg-deb)
```

Для end-to-end тестов нужен виртуальный интерфейс CAN:

```sh
sudo modprobe vcan
sudo ip link add dev vcan0 type vcan
sudo ip link set vcan0 mtu 72     # тесту CAN FD нужен MTU 72
sudo ip link set up vcan0
go test ./internal/e2e/
```

Без `vcan0` тесты socketcan и e2e пропускаются, поэтому `go test ./...`
остаётся зелёным и на машине без root.

## Конвенции кода

- один объект — один файл; константы и интерфейсы живут в файле своего
  объекта;
- table-driven тесты даже для одного кейса: проверяйте всё, что
  устанавливается, возвращается и доходит до моков, включая тексты и типы
  ошибок;
- доменные ошибки типизированы (`domain.Error`, sentinel'ы библиотек через
  `errors.Is`);
- комментарии и документация — на английском; русская документация
  зеркалит английскую файл за файлом;
- fuzz-тесты на парсеры (у парсера candump уже есть);
- payload кадров в логах — никогда.

## Pull request'ы

1. Форкните репозиторий и создайте ветку (`feat/tls-reload`).
2. Держите изменение сфокусированным; обновите тесты и обе языковые версии
   затронутой документации.
3. Убедитесь, что `make fmt vet test` зелёные; для изменений упаковки
   приветствуются `make cross` и `make deb`.
4. Откройте PR с кратким описанием: что изменилось, почему, как проверено.

`main` защищён: изменения попадают только через pull request'ы с зелёным CI.
