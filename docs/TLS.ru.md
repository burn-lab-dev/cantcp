# TLS 1.3

[English](TLS.md) | **Русский**

Разрабатывается **[BURN-LAB](https://burn-lab.ru)** — встраиваемый Linux:
драйверы, CAN и промышленная телеметрия.

У незащищённого потока cantcp нет шифрования и аутентификации (см.
[PROTOCOL.ru.md](PROTOCOL.ru.md)). Если сеть не полностью доверенная —
запускайте демон поверх TLS.

## Версия и шифры

- **Только TLS 1.3.** `MinVersion` и `MaxVersion` зафиксированы на 1.3 с
  обеих сторон; клиент TLS 1.2 отвергается на handshake. Понизить версию
  нельзя.
- Наборы шифров — умолчания Go для TLS 1.3 (AES-GCM и ChaCha20-Poly1305 с
  SHA-256/384). Они не выведены в конфигурацию: умолчания сильные, а
  настройка создаёт лишь способ их ухудшить.

## Режимы сервера

Режим TLS выбирается заданием пары сертификатов:

```sh
cantcpd --listen 0.0.0.0:29536 \
  --tls-cert /etc/cantcp/tls/server.pem \
  --tls-key  /etc/cantcp/tls/server-key.pem
```

Режим клиентских сертификатов задаёт `tls.client_auth` (`tls.client_auth` в
файле конфигурации):

| Режим | Поведение |
|---|---|
| `none` (по умолчанию) | сертификат у клиента не запрашивается; серверный сертификат всё равно доказывает клиенту подлинность сервера |
| `verify_if_given` | предъявленный клиентский сертификат проверяется по CA; клиент без сертификата допускается |
| `require_and_verify` | клиентский сертификат, подписанный CA, обязателен |

Оба проверяющих режима требуют `tls.ca_file` — CA, которым подписаны
клиентские сертификаты:

```sh
cantcpd --listen 0.0.0.0:29536 \
  --tls-cert /etc/cantcp/tls/server.pem \
  --tls-key  /etc/cantcp/tls/server-key.pem \
  --tls-ca   /etc/cantcp/tls/ca.pem \
  --tls-client-auth require_and_verify
```

`require_and_verify` — рекомендуемый режим для продакшена: он
аутентифицирует обе стороны. Демон не стартует, если сертификат, ключ или CA
не читаются либо ключ не соответствует сертификату.

## Режимы клиента

```sh
cantcp-cli listen --server can-gateway.example:29536 \
  --tls --tls-ca /etc/cantcp/tls/ca.pem

cantcp-cli send --id 123 --data 01 \
  --server can-gateway.example:29536 --tls \
  --tls-ca /etc/cantcp/tls/ca.pem \
  --tls-cert /etc/cantcp/tls/client.pem \
  --tls-key  /etc/cantcp/tls/client-key.pem
```

- `--tls` переводит соединение на TLS 1.3;
- `--tls-ca` заменяет системное хранилище доверия (для частного CA);
- `--tls-cert` / `--tls-key` добавляют клиентский сертификат для mTLS;
- `--tls-server-name` переопределяет имя, проверяемое по сертификату (по
  умолчанию — хост из `--server`);
- `--tls-insecure` отключает проверку. Существует для стендов с
  самоподписанными сертификатами; в любом другом применении соединение
  можно перехватить. Клиент пишет предупреждение при его использовании.

Имя сервера должно совпадать с subject alternative name (SAN) серверного
сертификата; команды генерации в [TLS-KEYS.ru.md](TLS-KEYS.ru.md) кладут в
SAN `localhost` и `127.0.0.1` и показывают, как добавить другие.

## Ротация сертификатов

После замены файлов пошлите `SIGHUP` (или `systemctl reload cantcpd`):
демон перечитает сертификат, ключ и CA и начнёт использовать их для новых
соединений. Установленные соединения сохраняют сессию; если новые материалы
сломаны, текущая конфигурация остаётся, а ошибка пишется в лог:

```sh
sudo systemctl reload cantcpd
journalctl -u cantcpd -n 5
```

Клиент перечитывает свои сертификаты только при запуске; для ротации
клиентского сертификата перезапустите клиент.

## Заметки о модели угроз

- TLS 1.3 даёт конфиденциальность, целостность и аутентификацию сторон (с
  mTLS). Он не добавляет защиту от повторов на уровне приложения: атакующий
  с ключами сессии или внутри аутентифицированной сессии может повторять
  кадры. Ограничивайте, кто может подключаться, и считайте саму шину CAN
  той границей безопасности, которой она является.
- Приватные ключи читает процесс демона; защищайте файлы (`chmod 600`,
  root или пользователь `cantcp`) и хост.
- Отзыв сертификатов вне области: при `require_and_verify` удалите клиентский
  сертификат из CA и перезапустите демон либо используйте CA с короткими
  сроками жизни сертификатов.
- Не допускайте `--tls-insecure` в продакшене и в комментариях кода: опция
  намеренно громко помечена в документации.
