# Черновики статей

[English](README.md) | **Русский**

> **Статус (2026-09-28):** план утверждён, черновики пишутся на следующей
> сессии (2026-09-29). Приоритетные темы — 1 (один конфиг, три источника) и
> 3 (безопасность шлюза).

Разрабатывается **[BURN-LAB](https://burn-lab.ru)** — встраиваемый Linux:
драйверы, CAN и промышленная телеметрия.

Рабочие заметки для цикла статей по этому проекту: каждый черновик начинается
с решения, которое действительно принято в коде, со ссылками на файлы.
Черновики живут здесь; опубликованные версии выходят на Хабре и ссылаются
обратно на репозиторий.

## Состав цикла

1. **Один конфиг, три источника, один валидатор.**
   Флаги, переменные `CANTCP_*` и строгий JSON-файл с задокументированным
   приоритетом; почему валидация живёт в домене
   (`internal/app/domain/config_*.go`) и как выглядят тексты ошибок. Код:
   `internal/config/`, `internal/app/domain/`.

2. **Гексагональная архитектура в маленьком Go-бинаре.**
   Слои, порты и адаптеры в проекте без фреймворков: domain → services →
   interfaces → adapters, ручной DI в `main`, table-driven тесты. Код: всё
   дерево `internal/`.

3. **Безопасность CAN-шлюза.**
   Почему CRC-8 — не целостность, что добавляют TLS 1.3 и mTLS, почему
   plain слушает loopback, как проектировались `--allow-plain` и таблица
   модели угроз. Код: `internal/adapters/tlsconfig/`,
   `internal/interfaces/tcp/`, `SECURITY.md`.

4. **Упаковка Go-бинарей: .deb без хелперов.**
   `CGO_ENABLED=0`, кросс-компиляция под amd64/arm64/armhf, POSIX-скрипт
   вокруг `dpkg-deb`, ужесточённый systemd-юнит и APT-репозиторий из
   `dpkg-scanpackages` + `apt-ftparchive` + GPG на GitHub Pages. Код:
   `scripts/`, `deb/`, `.github/workflows/`.

5. **vcan в CI: e2e-тесты без железа.**
   Как socketcan-адаптер, мост, TCP-листенер и клиент встречаются на
   виртуальной шине в раннере GitHub и почему тесты сами пропускаются без
   `vcan0` локально. Код: `internal/e2e/`.

## Конвенции

- черновик — отдельный файл с именем по теме;
- каждое утверждение о поведении ссылается на файл репозитория, который его
  реализует;
- русская версия опубликованной статьи живёт на Хабре; в репозитории
  остаются план и ссылки на код.

Решения по сессиям, из которых вырастают эти темы, записаны в журнале проекта
рабочего пространства BURN-LAB (`reflections/`) — статьи дистиллируются из
него.
