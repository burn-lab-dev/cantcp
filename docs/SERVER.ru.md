# Демон cantcpd

[English](SERVER.md) | **Русский**

Разрабатывается **[BURN-LAB](https://burn-lab.ru)** — встраиваемый Linux:
драйверы, CAN и промышленная телеметрия.

## Что делает демон

`cantcpd` связывает один интерфейс Linux SocketCAN и TCP-клиентов:

- кадры, прочитанные с шины CAN, рассылаются всем подключённым клиентам
  пакетами cantcp (см. [PROTOCOL.ru.md](PROTOCOL.ru.md));
- пакеты cantcp, полученные от клиента, записываются в шину CAN и через
  loopback SocketCAN (`CAN_RAW_RECV_OWN_MSGS`) рассылаются всем клиентам,
  включая отправителя: все клиенты видят полный трафик шины, проходящий
  через шлюз, а не только кадры других узлов.

Всё остальное — статистика, health-check, мониторинг — отдаётся отдельным
HTTP-листенером. Сам поток кадров остаётся минимальным.

## Один интерфейс на экземпляр

Один процесс демона обслуживает ровно один интерфейс CAN. Для нескольких
шин запускаются несколько экземпляров, каждый со своим юнитом и конфигом:

```sh
cantcpd --config /etc/cantcp/can0.json --can can0 --listen 127.0.0.1:29536
cantcpd --config /etc/cantcp/can1.json --can can1 --listen 127.0.0.1:29546
```

В systemd это instance-юниты (`cantcpd@can0.service`) или отдельные юниты.
Изоляция по процессу даёт чистую область отказа: проблема на одной шине не
затрагивает другие, у каждого экземпляра свои лимиты и порты.

## Режимы соединения

Режимы взаимоисключающие; режим выбирается наличием TLS-настроек:

- **plain** — когда сертификат не задан. Кадры идут без шифрования и
  аутентификации: только доверенный периметр. По умолчанию слушает
  `127.0.0.1:29536`; внешний адрес требует явного флага `--allow-plain`,
  иначе демон не стартует:
  `listen: plain mode on "0.0.0.0:29536" is not loopback; set allow_plain or
  configure TLS`;
- **TLS 1.3** — когда заданы `tls.cert_file` и `tls.key_file`. TLS 1.2 и
  старше отвергаются. Клиентские сертификаты опциональны, проверяются или
  обязательны по `tls.client_auth`. См. [TLS.ru.md](TLS.ru.md).

## Управление потоком и лимиты

- У каждого клиента ограниченная очередь кадров (`limits.client_queue`, по
  умолчанию 1024). При переполнении кадр отбрасывается только для этого
  клиента и растёт счётчик `cantcp_dropped_frames_total`: медленный клиент
  не блокирует шину и других клиентов.
- `limits.max_connections` ограничивает число одновременных клиентов;
  соединение сверх лимита принимается и сразу закрывается.
- `limits.idle_timeout` закрывает молчащего клиента (0 — выключено, по
  умолчанию).
- `limits.read_timeout` ограничивает TLS-handshake; `limits.write_timeout` —
  одну запись кадра.
- `limits.max_frames_per_second` ограничивает поток кадров от одного клиента
  в шину CAN; лишние отбрасываются и считаются (0 — выключено).

## Сигналы

- `SIGINT`, `SIGTERM` — корректное завершение: листенеры останавливаются,
  соединения закрываются, CAN-сокет освобождается.
- `SIGHUP` — перечитывание. Демон заново читает те же источники конфигурации
  и применяет:
  - файлы TLS-сертификата, ключа и CA (ротация без рестарта);
  - уровень логов;
  - лимиты (действуют для нового трафика и следующих accept'ов).
  Адрес прослушивания, интерфейс CAN, переключатель TLS и адрес статистики
  фиксированы на время жизни процесса. Неудачное перечитывание (ошибка
  валидации) сохраняет текущие настройки и пишет ошибку в лог.

## Проверки при старте

Демон проверяет всю конфигурацию до начала работы, затем:

1. открывает и привязывает интерфейс SocketCAN, включая кадры ошибок, если
   настроено;
2. загружает TLS-пару и CA (когда выбран TLS);
3. открывает TCP-листенер и HTTP-листенер статистики;
4. запускает мост (читатель CAN) и циклы accept.

Ошибка на любом шаге логируется, процесс завершается с ненулевым кодом.
Тихой деградации нет: недоступный интерфейс CAN — ошибка старта.

## Статистика

HTTP-листенер отдаёт `/healthz`, `/api/v1/stats` и `/metrics`; см.
[STATS.ru.md](STATS.ru.md). Включён по умолчанию на `127.0.0.1:29537`,
выключается `--no-stats`, переносится `--stats-listen`.

## Логи

Логи пишутся в stderr через `log/slog`: текст (по умолчанию) или JSON.
Payload кадров не логируется никогда; уровень debug добавляет события
соединений, трассировочный уровень библиотеки демон не использует. Для
journald удобен текст, для сборщиков — JSON.

## Развёртывание

Пакет ставит `/usr/bin/cantcpd`, конфигурацию `/etc/cantcp/cantcpd.json`,
ужесточённый systemd-юнит и man-страницу. См. [DEPLOY.ru.md](DEPLOY.ru.md).
